Yake 玻璃瑕疵檢測系統 — 交接文件

白斑（Yake）瑕疵自動檢測 pipeline ＋ Web 品管／戰情 UI ＋ PostgreSQL，完整技術交接。

最後更新：2026-07-03 ・ 本文件反映當日全面檢查與修復後的程式碼狀態 ・ 搭配 CLAUDE.md（AI 協作摘要）與 schema.sql（DDL）閱讀

1系統是什麼

Yake 是一套玻璃基板白斑瑕疵的檢測與可視化系統。一句話描述三個組件的分工：

🏭 Pipeline（process.py）是生產線 — 掃描產線原圖、沿長邊切 20 塊、逐塊跑白斑檢測、依 NG/GRAY/OK 分流存檔並批次寫入 PostgreSQL。

🔍 Visual 分頁是品管站 — 載入切好的區塊，即時拉閥值滑桿做「二次確認」，滿意後按「儲存」把人工確認的結果覆寫回 DB。

📊 Dashboard 分頁是戰情室 — 從 DB 撈記錄，畫出玻璃四邊（Y1/Y2/X1/X2）× Shot 區間的缺陷空間分布、可鑽取到基板 ID 明細。

PostgreSQL 的 detection_records 表是唯一的資料真相，兩個 UI 分頁都消費同一張表。

2整體架構

DB 寫入只有兩個入口

⚠ 鐵律：/api/detect 絕對不寫 DB 拖動滑桿每次鬆手都會打 /api/detect，如果它寫 DB，一次調參就會炸出上百筆垃圾記錄（這是 2026-07-02 修掉的歷史 bug，別改回去）。寫入只有： ① process.py pipeline 主流程的 bulk_insert_records()；② Visual 儲存鈕的 POST /api/save-detection。 兩者現在都有覆寫語意：同一 segment_path 重跑／重存會取代舊記錄，不會累積重複。

5命名規則（核心業務邏輯）

整個系統的欄位推導全部掛在檔名與路徑的約定上，這一節是最不能改壞的部分。

5.1 Segment 檔名解剖

Pipeline 輸出的每個切割區塊檔名為固定格式（由 split_and_detect_single 組出、由 parse_segment_filename 解回）：

20250401date（8 碼） _ 00hour（2 碼） _ C2QX45Y311011601board_id（基板） _ Y2side（四邊） _ CenterImage001_Shot002_021base_name（原圖檔名，內含底線！） _ 05segment_index（01..20） .jpg
⚠ 為什麼不能用 split('_') 一路拆到底 base_name 本身含底線（CenterImage001_Shot002_021），所以解析必須用「固定位置」邏輯：前 4 段（date, hour, board_id, side）＋最後 1 段（segment_index）固定，中間全部 join 回去當 base_name。唯一的正確實作是 process.parse_segment_filename()，server 的 /api/save-detection 也用它 — 需要解析檔名時一律呼叫它，不要自己寫。

產線原圖的路徑約定（pipeline 輸入側）：

<input_folder>\<date>\<hour>\<board_id>\<side>\CenterImageXXX_ShotYYY_ZZZ.jpg
                └ 20250401  └ 00   └ C2QX...   └ Y2（倒數第二層就是 side）

shot_number 推導：每個 shot_label 名義上涵蓋 20 個實體 shot，原圖切成 20 塊剛好一塊對應一個 shot：

shot_number = 區間起點 + segment_index − 1     # 再 clip 到區間終點
# 例：Shot002_021 的第 5 塊 → 2 + 5 − 1 = 6
# 例：Shot182_185 的第 20 塊 → clip 到 185（末段不足 20 個 shot）

實作：process._shot_number_for_segment()。

5.3 玻璃四邊與 Dashboard 的對應

⚠ Dashboard 上的點位不是真實座標 recordsToDefects() 只用 shot_label 的中點決定「沿邊方向」的位置，再用確定性雜湊把點撒在邊緣帶 0..70mm 內 — 純視覺呈現。要顯示真實位置需做 bboxes → 玻璃物理座標的映射（Roadmap 第 3 項）。

9程式碼詳解

9.1 split.py 基座模組

負責「找到要處理的圖」與所有 config/log/cache 檔的讀寫。process.py 建構在它之上。模組級常量：SPLIT_CONFIG_FILE、SPLIT_LOG_FILE、SPLIT_CACHE_FILE（三個 JSON 檔名）、DEFAULT_SPLIT_SIZE=20。

setup_logging(log_path: Optional[str]) → None
初始化 logging：Console handler 必開，log_path 有給就加開 UTF-8 檔案 handler。force=True 讓重複呼叫可重設（子進程／重入安全）。
load_config(config_file) → Dict ／ load_split_log(log_file) → Dict ／ save_split_log(log_data, log_file)
JSON 讀寫三兄弟。讀取失敗一律回傳空 dict／預設結構並記 log，不會拋例外（呼叫端用空 dict 判斷要不要終止）。split_log 結構：{last_updated, processed_dates[], total_images_split, total_segments}，每跑一輪 append 一筆統計。
load_file_cache(cache_file) → Dict ／ save_file_cache(cache_data, cache_file) ／ get_dir_mtime(dir_path) → float ／ should_refresh_cache(cache_data, input_folder, date) → bool
檔案掃描快取。快取結構：{source_path, last_global_scan, date_caches: {date: {cached_at, nas_mtime, file_count, files[]}}}。 should_refresh_cache 在三種情況要求重掃：來源路徑變了、該日期沒快取、該日期目錄 mtime 變了。 注意：Windows/NAS 上「子目錄內」新增檔案不會改變日期目錄本身的 mtime，快取可能過期不自知 — 這就是目前 config 停用快取（enable_file_cache=false）的原因；要開就要記得 --refresh-cache。
extract_path_meta(file_path) → Dict[str, str]
從路徑「倒數第幾層」抽 meta：hour=parts[-4]、board_id=parts[-3]、position=parts[-2]（即 side）；若 parts[-5] 是 8 位數字再補 date。先把 / 統一成 \ 再切。層數不足回空 dict — 呼叫端（process.py）會以 "UNKNOWN" 補預設值並因此跳過 DB 寫入。
is_valid_image(file_path, cfg) → bool
兩道過濾：① 檔名必須以 valid_prefixes 其中之一開頭；② 檔名結尾的連續數字段若落在 exclude_suffix 黑名單則排除（如尾碼 001 是校正圖）。
read_image(image_path) → Optional[np.ndarray] ／ save_image(output_path, img) → bool
讀圖走 PIL 開檔 → 轉 RGB → cv2 轉 BGR（PIL 對中文路徑/特殊格式容錯較好，cv2.imread 在 Windows 非 ASCII 路徑會失敗）；存圖用 cv2.imwrite。讀失敗回 None、存失敗回 False，皆記 log 不拋錯。
scan_images_by_date(input_folder, date_start, date_end, cfg, cache_data, enable_cache) → (List[str], Dict)
主掃描器。把日期範圍展開成每一天，逐日決定「用快取 or 重掃」；重掃時用 glob **/*.jpg（含大寫副檔名）遞迴收檔 → is_valid_image 過濾 → 更新該日快取。回傳（排序去重後的全部路徑，更新後的快取資料）。
split_single_image(args) / split_images(...) / main() 獨立模式
split.py 自己也能當獨立程式跑（python split.py）：只切割存檔、不做偵測、不寫 DB。實務上已由 process.py 取代，保留當 debug 工具（例如想先確認切割結果再開偵測）。

9.2 process.py Pipeline 主體

偵測核心（§6 的實作）

DEFAULT_THRESHOLD=100 ／ DEFAULT_LEN_GRAY_MIN=5 ／ DEFAULT_LEN_NG=10 ／ DEFAULT_AREA_GRAY_MIN=20 ／ DEFAULT_AREA_NG=40 ／ DEFAULT_MERGE_DIST=30
config 未指定時的閥值預設，與 server.DetectParams 的預設一致（改預設值兩邊都要看）。
_make_uf / _find / _union ／ _box_dist(b1, b2) → float ／ _merge_boxes(raw_boxes, max_dist) → List[box]
Union-Find（路徑減半優化）做 bbox 聚合。_box_dist 算兩框的最短歐氏間距（重疊為 0）；_merge_boxes 對所有框做 O(n²) 兩兩比距、距離 ≤ max_dist 者 union，每群取外接框。box 格式為 (x0, y0, x1, y1)。
_classify_spot(w, h, area, params) → "NG"|"GRAY"|"OK"
§6 表格的分級規則實作。params 必須含 len_ng / len_gray_min / area_ng / area_gray_min 四鍵。
detect_defect_full(img_bgr, params, return_mask=False) → Dict
偵測演算法唯一入口。回傳 {status, ng_count, gray_count, bboxes[]}；return_mask=True 額外附 {mask, img_w, img_h}（給 server 的 /api/detect 疊圖用）。灰階用三通道平均，所以 BGR（pipeline）與 RGB（server 的 PIL）餵進來結果相同。bboxes 內每項：{x0, y0, w, h, area, status}。
_build_detect_params(cfg) → Dict
把 split_config.json 的閥值欄位（white_threshold → threshold 等）收斂成偵測參數 dict，缺的補預設。pipeline 與 server /api/default-params 共用。

命名解析（§5 的實作）

_parse_shot_label(base_name) → Optional[str] ／ _shot_number_for_segment(shot_label, segment_index) → Optional[int] ／ _derive_side_from_path(image_path) → Optional[str]
分別為：從檔名 regex 抓 Shot(\d+)_(\d+)；區間起點＋index−1 再 clip 到終點；取路徑倒數第二層並驗證 ∈ {X1,X2,Y1,Y2}（不合法回 None，不再有猜測 fallback — 舊的 _placeholder_side 會亂寫 Y2 進 DB，2026-07-03 已移除）。
parse_segment_filename(path) → Optional[Dict]
Canonical parser（§5.1）。把 segment 檔名解成 DB 欄位 dict：date, hour, substrate_id, side, image_layer, source_image, shot_number, shot_label, segment_index。前 4 段＋最後 1 段固定、中段 join 回 base_name。side 不合法或段數不足回 None（server 收到 None 回 400）。

Pipeline 執行

split_and_detect_single(args=(image_path, output_folder, cfg)) → Dict　【子進程執行】
單張圖的完整處理：讀圖 → 抽 meta → 沿寬度切 split_size 塊（最後一塊吃餘數）→ 每塊 detect_defect_full → 等級 ∈ defect_status_to_save 者存檔（檔名=§5.1 格式）→ 組出該塊的完整 DB record。 回傳 {filename, status, segments_count, ng_segments, gray_segments, saved_kake, records[], records_skipped, error}。 重點設計：子進程不碰 DB（records 帶回父進程集中寫）；inspect_ts 由 date+hour 組出（產線時間）；任一必填 meta 缺漏 → db_writable=False，整張圖的 records 跳過、只計入 records_skipped（檔案照常輸出）。
run_pipeline(input_folder, output_folder, date_start, date_end, cfg, log_data, cache_data, limit) → (stats, cache_data)
單一日期範圍的主流程：掃描 →（可選）截斷至 limit 張 → 開一個 ProcessPoolExecutor（整輪共用一個，chunk 只是 DB 批次分段）→ 每 chunk 收齊 records 後 bulk_insert_records → 統計寫入 log_data。DB pool 開失敗只警告並跳過寫入，不中斷切割。回傳統計 dict：{total, success, failed, segments, ng_segments, gray_segments, saved_kake, db_inserted}。
parse_limit(value) → Optional[int] ／ main()
CLI 進入點。參數：--limit（正整數或 all/0/none=不限）、--refresh-cache（清快取重掃）、--config（換配置檔）。main 依 date_ranges 逐範圍呼叫 run_pipeline，結束時存 split_log 與（若啟用）檔案快取。freeze_support() 是 Windows multiprocessing 必要呼叫。

9.3 db.py 資料層

_dsn() → str ／ _make_pool() ／ open_pool() ／ close_pool() ／ get_conn()（contextmanager）
連線池生命週期。DSN 由 .env（python-dotenv 載入）組出。 2026-07-03 修正：psycopg_pool 的 ConnectionPool close 後不能重 open（PoolClosed），舊寫法在多 date_range pipeline 第二輪起會靜默跳過 DB 寫入。現在 pool 為 lazy 全域變數，open_pool() 發現池子關閉就換一顆新的；get_conn() 也會自動補開。 pool.connection() context manager 出區塊時自動 commit（例外則 rollback）。
fetch_records(limit=700) → List[Dict] ／ _row_to_record(row) → Dict ／ count_records() → int
撈最近 N 筆（ORDER BY inspect_ts DESC，吃 idx_dr_inspect_ts 索引）。_row_to_record 把 DB row 整形成前端 JSON（inspect_ts → ISO 字串）。
insert_record(rec: Dict) → int ／ _UPSERT_CLAUSE
單筆寫入（/api/save-detection 與 /api/records 的後盾），JSONB 欄位自動 Json() 包裝。 覆寫語意（upsert）：靠 ux_dr_segment_path 唯一索引走 ON CONFLICT (segment_path) WHERE segment_path IS NOT NULL DO UPDATE — Visual 重按儲存是「更新既有列」（id 不變），不是新增重複。共用的 SET 子句抽在 _UPSERT_CLAUSE。
bulk_insert_records(records: Iterable[Dict]) → int
Pipeline 批次寫入（executemany），同樣帶 _UPSERT_CLAUSE — 重跑 pipeline 不累積重複。 容錯：整批失敗（如 NOT NULL violation）時降級為逐筆插入，壞的跳過記 log — 一筆壞資料不再拖垮整個 chunk。回傳實際成功筆數。 注意：同一批內不可出現重複的 segment_path（ON CONFLICT 限制「同列不可被影響兩次」）；pipeline 每塊只產一筆，天然滿足。
distinct_hours(date_from=None, date_to=None) → List[str]
回傳實際有資料的 hour 清單（補零字串、字典序），可用日期界定範圍。供 Dashboard 顯示「時段缺口」提示。

9.4 server.py FastAPI 後端

啟動：python -m uvicorn server:app --port 8000 --host 127.0.0.1（開發時可加 --reload）。DB pool 的開關掛在 lifespan（啟動開、關閉收）。endpoint 明細見 §10，這裡講非 endpoint 的部分：

DetectParams（pydantic）／ DetectRequest ／ SaveDetectionRequest ／ RecordIn
請求模型。DetectParams 六個欄位的預設值＝process.py 的 DEFAULT_*；RecordIn 是通用寫入（/api/records POST）的完整欄位模型，inspect_ts/date/hour 缺省時以 server 當下時間補齊。
